## 关键事实：`--context-length` 不持久，模型重载会回到 241920
- 03:11 诊断「30 份测试集 CV 打标 5.5 分钟仍 0 份完成」：`lms ps` 显示 `qwen/qwen3.5-9b` 的 **CONTEXT = 241920**（不是之前设的 16384），显存吃到 **15.7 / 16.3 GB**，GPU 100% 但吞吐塌到 1–2 tok/s。
- 原因：`lms load --context-length 16384` 只在当次加载生效；LM Studio 若因换模型/重启等原因 JIT 重载，会按模型默认（≈240K）重新分配 KV cache。
- **永久解法只能改 LM Studio 里该模型的加载配置（UI 里设 context length 并保存），命令行参数不可靠。**
- 判断「打标是否真在跑」的三个客观指标：`lms ps` 的 CONTEXT、`nvidia-smi` 显存占比、`db/label_cv/<组>/` 文件数是否增长。前端进度条只在单个文件完成后才跳动，0% 不代表没开始。
- 03:19 已修：`lms unload` + `lms load --context-length 16384 --gpu max`（加载 46s），`lms ps` 回到 CONTEXT 16384 / 6.55 GB，实测 **36.4 tok/s**（此前 1–2）。GPU 显存 9.8/16.3 GB。
- **复发条件**：LM Studio 因换模型（打标第二阶段要调 nomic-embed）或重启而 JIT 重载 qwen 时，很可能又按 241920 加载。每次开始批量打标前先 `lms ps` 看一眼 CONTEXT 是否为 16384。

## BUG（已修）：上传 JD 时语义维恒为 0.5
- 现象：服务台日志反复出现 `embedding 失败，语义维退化为中性值: module 'extract' has no attribute 'jd_text'`。

- 已改：`pipeline.py` 第 21 行加 `import embed as EMB`，第 98 行改为 `return EMB.jd_text(obj, raw)`。
- 修复验证：现场算出的向量与标签文件里的向量余弦 **0.999247**（embedding API 有微小数值非确定性，不是错误）；用两者分别算 Top-5 **完全一致**。
